Login startup and resource follow-up — 2026-10-25

The supplied macOS report identifies the GUI launched by io.github.victoriousian.ieum.login. Termination is CODESIGNING, code 4, Launch Constraint Violation, before application code runs. The report has no Team ID. The large Guard reservation is virtual address space, not resident RAM; neither that reservation nor the shared-cache reporting error diagnoses a leak. A stale requirement after an ad-hoc alpha replacement is consistent with the existing direct-executable LaunchAgent design.

Startup change

Use SMAppService.mainAppService for the GUI application login item. Reconcile the saved preference, then retire the former agent, including when the main app is already enabled or awaiting approval. Register the replacement first because unregistering the old agent can terminate its process. Cleanup is attempted even if the new registration fails; errors remain visible to the caller and the next reconciliation retries failed cleanup. The old plist stays bundled solely to identify the service to unregister.

Capture the launch Apple Event during the AppKit launch notification and defer opening the window until its login context is known. This preserves background startup without depending on a --background argument that mainAppService does not supply. Native observation begins before QApplication, so startup dialogs cannot consume the launch event first. Offscreen/minimal tools bypass the wait.

The package smoke check now invokes the GUI's --version as well as the core's, in addition to verifying the sealed bundle. This exercises both loaders but does not test a real login or prove that ServiceManagement registration works.

API references: mainAppService, launch Apple Event constants. Apple also documents a launch-constraint failure after updating a registered service.

Resource change and measurements

The hidden log queue now retains at most 256 Ki UTF-16 code units (plus its omission notice), still bounded by 2,000 entries. It evicts oldest entries so the latest failure survives. Rendered text is bounded by 1 Mi code units and 10,000 blocks. The original log file is unaffected.

Native file-change notifications still deliver appended lines immediately. When both file and directory watches exist, the fallback timer checks every 30 seconds instead of every 2 seconds. Missing watches use the 2-second recovery interval; the directory watch is retried if the parent directory appears later. Windows retains its existing 2-second interval even with registered watches: the first native Windows CI exposed a file-tail regression when trusting watch registration for a 30-second interval. Windows test diagnostics are forced to stderr so future failures include the individual failing case.

Both builds use Debian 13 x86-64, GCC 14, Qt 6.8.2, and Debug configuration. The baseline is d9578dec4e6928579a1822615b4a297ec71aa25f, with only the existing resource-probe target enabled. Baseline binaries were preserved before production edits. The probe source is identical in both builds. No compilation or tests ran during the comparison. The shared cloud environment's other load is uncontrolled.

Burst results are medians of 3 runs per build in alternating order. The hidden log workload is 2,000 lines of 16,384 payload characters, truncated to the existing per-line display limit. RSS covers the whole probe process, not just the queue. CPU time includes workload cleanup.

No general idle CPU improvement or native macOS saving is established.
