# 설치와 첫 연결

사용할 컴퓨터 모두에 이음을 설치하세요. 키보드와 마우스가 연결된 컴퓨터는 **호스트**,
그 입력을 받는 컴퓨터는 **클라이언트**입니다. 앱의 **처음 연결하기**에서도 절차를 볼 수 있습니다.

## 설치 파일 고르기

[릴리스 페이지](https://github.com/Cherry-Company/ieum/releases)에서 사용할 릴리스를 열고
운영체제와 CPU에 맞는 파일을 받으세요. 서로 연결할 컴퓨터는 같은 이음 버전을 사용하세요.

| 컴퓨터 | 받을 파일 |
| --- | --- |
| Windows · Intel/AMD | `win-x64` MSI. 한국어 설치 화면은 `ko-KR` 파일 |
| Windows · Snapdragon 등 ARM | `win-arm64` MSI |
| Mac · M1 이후 | `macos-arm64` DMG. 현재 빌드는 macOS 14 이상 대상 |
| Mac · Intel | `macos-x86_64` DMG. 현재 빌드는 macOS 12 이상 대상 |
| Linux | 배포판에 맞는 DEB·RPM·Arch 또는 Flatpak. 실험적 지원 |

Windows의 CPU 종류는 **설정 → 시스템 → 정보 → 시스템 종류**에서,
Mac은 **Apple 메뉴 → 이 Mac에 관하여**에서 확인할 수 있습니다.

## Windows 설치

1. MSI를 실행해 설치한 뒤 시작 메뉴에서 이음을 엽니다.
2. Visual C++ 런타임이 없다는 오류가 나오면 CPU에 맞는 Microsoft 설치 파일을 실행합니다.
   [x64 런타임](https://aka.ms/vs/17/release/vc_redist.x64.exe) ·
   [ARM64 런타임](https://aka.ms/vs/17/release/vc_redist.arm64.exe).
   런타임은 현재 MSI에 포함되지 않으므로, 이미 설치되어 있다면 다시 설치할 필요가 없습니다.
3. 호스트에 방화벽 허용 안내가 나오면 사용할 네트워크에서 연결을 허용합니다.

현재 알파 설치본은 Windows 코드 서명 전입니다. 설치 경고가 나오면 공식 릴리스에서 받은 파일인지
확인하고 [다운로드 파일을 검증](#다운로드-파일-검증)하세요.

MSI의 서비스 모드는 로그인 화면에서 입력을 공유할 때 사용합니다. 역할과 주소를 한 번 설정하고
시작해야 사용할 구성이 저장됩니다. 무설치본에는 서비스가 포함되지 않습니다.
서비스·로그인 화면 동작은 사용 중인 Windows 환경에서 확인해야 합니다.

## macOS 설치

1. DMG를 열고 이음을 **Applications**로 옮깁니다. DMG 안에서 계속 실행하지 마세요.
2. Applications의 이음을 엽니다. 현재 알파는 Apple 서명·공증 전이므로 설치 경고가 나올 수 있습니다.
   공식 파일과 체크섬을 확인한 뒤 시스템 설정의 안내에 따라 실행하세요.
3. **시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용**에서 현재 이음 앱을 허용합니다.
4. 호스트에서 입력 모니터링 권한을 요청하면 현재 앱에 허용하고 이음을 다시 실행합니다.

이음은 키보드·마우스 공유를 위해 손쉬운 사용과 입력 모니터링을 이용합니다.
화면 스트리밍을 하지 않으므로 화면 기록·카메라·마이크·전체 디스크 접근 권한은 요구하지 않습니다.

업데이트 뒤 이전 앱의 권한만 남으면 이음 권한 안내의 **이전 승인 초기화**를 이용하거나,
손쉬운 사용에서 이전 항목을 제거하고 Applications의 현재 앱을 다시 추가하세요.
앱이 표시되지 않을 때는 권한 안내의 **Applications에서 이음 앱 보기**와 **손쉬운 사용 설정 열기**를 이용하세요.

“손상되어 열 수 없음” 안내가 나오면 받은 파일의 체크섬부터 확인하고 다시 다운로드하세요.
설치 경고를 없애려고 시스템 전체 보안 설정을 끄지 마세요.

로그인할 때 실행은 사용자 로그인 이후에 동작합니다. FileVault 해제 화면은 macOS가 시작되기 전의
환경이므로 이음으로 조작할 수 없습니다.

### 로그인 직후 `Launch Constraint Violation`이 나올 때

충돌 보고서의 `Process`가 `Ieum`, `Coalition`이 `io.github.victoriousian.ieum.login`,
종료 사유가 `CODESIGNING, Code 4, Launch Constraint Violation`이면 기존 로그인 실행 등록을
확인해야 합니다. macOS가 앱 코드 실행 전에 차단한 것이므로, 보고서 뒤쪽의 큰 `Guard` 가상
메모리 수치를 실제 RAM 사용량으로 해석하지 마세요.

수정본을 설치하기 전에는 Applications에서 이음을 수동으로 열고 **설정 → 일반 → 로그인할 때 실행**을
꺼서 이전 실행 항목을 해제할 수 있습니다. 이후에는 필요할 때 앱을 직접 실행하세요.

이 수정이 포함된 빌드는 앱 자체를 macOS 로그인 항목으로 등록하고 이전 LaunchAgent를 해제합니다.
Applications의 앱을 교체한 뒤 한 번 수동으로 열어 이전 등록을 정리하고, 자동 실행을 꺼 두었다면
다시 켜세요. macOS에서 승인을 요구하면 **시스템 설정 → 일반 → 로그인 항목**에서 이음을 허용합니다.
정리 실패가 표시되면 등록이 끝난 것으로 간주하지 말고 오류 내용을 확인하세요.

업데이트 후 재부팅·로그인하여 이음이 한 번만 시작되는지, 창을 열지 않아도 메뉴 막대와 연결이
돌아오는지 확인해야 합니다. 소스 수정이나 Linux 테스트 통과만으로 해당 Mac에서의 해결을 보장하지 않습니다.

## Linux 설치

패키지 관리자가 의존성을 함께 설치하도록 내려받은 파일을 지정하세요.

```sh
# Debian / Ubuntu
sudo apt install ./Ieum-*.deb

# Fedora
sudo dnf install ./Ieum-*.rpm

# Arch Linux
sudo pacman -U ./Ieum-*.pkg.tar.zst
```

Flatpak은 받은 파일을 `flatpak install --user ./파일명.flatpak`으로 설치하고
`flatpak run org.deskflow.deskflow`로 실행합니다. 앱 ID는 호환성을 위해 유지합니다.
Wayland에서 입력 캡처·원격 데스크톱 포털이 열리면 사용할 화면과 입력 권한을 승인하세요.

Flatpak 안에서는 호스트의 Tailscale 명령이 보이지 않을 수 있습니다. Tailscale 기기 목록을 사용할
때는 네이티브 패키지를 권장합니다. [직접 빌드하기](../dev/build.md).

## 같은 공유기에서 연결

1. **호스트:** `내 키보드와 마우스 공유`와 **로컬 네트워크**를 고르고 **시작**을 누릅니다.
2. **클라이언트:** `다른 컴퓨터의 키보드와 마우스 사용`과 **로컬 네트워크**를 고릅니다.
   호스트에 표시된 이름이나 IP를 입력하고 **연결**을 누릅니다.
3. 양쪽에 표시된 인증서 지문을 비교해 승인합니다.
4. 호스트의 **컴퓨터 배치**에서 클라이언트의 **이 기기** 이름을 그대로 입력합니다.
   실제 책상의 방향을 고르고 **컴퓨터 추가**를 누른 뒤 저장합니다.
5. 그쪽 화면 끝으로 마우스를 옮깁니다. 키보드도 같은 컴퓨터로 넘어갑니다.

위치를 바꿀 때는 컴퓨터 카드를 드래그하거나, 선택한 뒤 화살표 버튼을 누르세요.
**선택한 컴퓨터 설정**에서 이름·별칭과 해당 컴퓨터의 키보드 옵션을 바꿀 수 있습니다.

## Tailscale로 연결

1. 두 컴퓨터에서 Tailscale을 실행하고 같은 Tailnet에 로그인합니다.
2. 양쪽 이음의 연결 방법을 **Tailscale**로 고릅니다.
3. 호스트에서 **시작**을 누르고, 클라이언트에서 그 호스트를 고른 뒤 **연결**을 누릅니다.
4. 지문 승인과 컴퓨터 배치는 로컬 연결과 같습니다.

Tailscale의 온라인 표시는 이음이 호스트로 실행 중이라는 뜻이 아닙니다.
Tailnet ACL과 호스트 방화벽에서 TCP `24800`을 허용해야 합니다.

클라이언트가 이미 다른 호스트에 연결되어 있다면 **클라이언트에서** 호스트를 바꾸세요.
기존 연결을 종료한 뒤 새 호스트에 자동으로 연결합니다. 전환·재시도 중에는 취소할 수 있습니다.
한 클라이언트는 한 번에 한 호스트를 사용합니다.

## 설정과 문제 해결

메인 화면의 바로가기를 쓰거나 **모든 설정**에서 검색하세요. 검색 결과를 선택하면 해당 항목으로
이동합니다. 업데이트 확인은 **일반** 설정에서 직접 켤 수 있습니다.

| 증상 | 확인할 곳 |
| --- | --- |
| 호스트가 기다리기만 함 | 클라이언트에서 이 호스트를 선택했는지, 다른 호스트에 연결된 것은 아닌지 확인 |
| Tailscale 기기는 보이지만 연결되지 않음 | 상대 이음의 호스트 시작 상태, Tailnet ACL과 방화벽 확인 |
| 연결됐지만 화면을 넘어가지 않음 | 호스트의 컴퓨터 배치에 클라이언트의 이름과 방향이 맞는지 확인 |
| Mac에서 입력이 전달되지 않음 | Applications의 현재 앱에 손쉬운 사용·입력 모니터링 권한이 있는지 확인 |
| 포트를 바꿀 수 없음 | Tailscale이 관리하는 값인지 확인. 로컬 연결로 전환한 뒤 네트워크 설정 확인 |
| 창을 닫아도 실행 중임 | 창 설정의 닫기 동작 확인. 완전히 종료하려면 앱 메뉴나 트레이·메뉴 막대에서 종료 선택 |
| 충돌 또는 알 수 없는 오류 | **도움말 → 오류 보고**에서 진단 확인·복사·저장. Mac에서는 충돌 보고서도 확인 |

오류 보고 창의 **복사 후 GitHub 열기**를 누르고, 이슈에 진단과 당시 상황을 붙여 넣어 제출하세요.
브라우저가 열리지 않아도 같은 창의 주소와 저장 기능을 사용할 수 있습니다. 자동 업로드는 없습니다.
공유 전에 내용을 확인하세요. [보안 정책](../SECURITY.md) · [실기 검증 항목](reliability-validation.md).

## 다운로드 파일 검증

선택한 릴리스에 첨부된 `SHA256SUMS.txt`에서 받은 파일과 같은 이름의 해시를 찾으세요.
아래 명령의 파일명을 실제 받은 파일명으로 바꿔 실행하고 결과를 비교합니다.

```powershell
Get-FileHash '.\받은파일.msi' -Algorithm SHA256
```

```sh
# macOS
shasum -a 256 ./받은파일.dmg

# Linux
sha256sum ./받은파일.deb
```
