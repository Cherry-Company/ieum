# 안정성과 연결 전환 확인

이 문서는 수정 후 실제 Windows·macOS 컴퓨터에서 확인할 항목입니다.
Linux 빌드·단위 테스트 통과가 아래 실기 결과를 대신하지 않습니다.

## 2026-10-25 재부팅 오류와 자원 사용 후속 수정

추가로 받은 보고서에서 GUI를 실행한 이전 로그인 에이전트가
`CODESIGNING / Code 4 / Launch Constraint Violation`으로 차단되는 것을 확인했습니다.
이는 앱 코드 실행 전의 macOS 실행 제약 오류입니다. 기존의 부팅 ID·종료 기록 처리가
이 오류를 해결했다는 의미는 아닙니다.

자동 실행 등록은 `SMAppService.mainAppService`로 바꾸고 이전 에이전트 등록을 정리합니다.
로그인 Apple Event를 받아 백그라운드 시작을 유지합니다. 새 등록이 이미 있거나 실패했어도
이전 항목 정리를 시도하며, 정리 실패는 성공으로 처리하지 않습니다.
로그인 항목 이전 순서·실패·재시도·자동 실행 끄기를 Linux에서 대체 서비스로 검사했습니다.
실제 ServiceManagement 호출과 로그인 이벤트 전달은 Mac에서 확인해야 합니다.

로그는 숨겨진 대기열을 256 Ki 문자, 표시 문서를 1 Mi 문자로 제한하고 최신 내용을 남깁니다.
파일 감시가 동작하면 보조 확인 주기는 30초이며, 감시가 없으면 2초 간격으로 복구를 시도합니다.
운영체제의 파일 변경 알림은 즉시 처리합니다. 원본 로그 파일은 이 표시 제한의 영향을 받지 않습니다.

이번 Linux Debug 전체 CTest 결과는 74개 프로그램 중 72개 통과입니다.
기존 `ServerProxyTests`와 `ServerTests`는 테스트가 `CoreIpcServer` 싱글턴을 만들지 않아
assertion에서 종료되며, 환경 구성 때도 같은 실패가 기록되어 있습니다. 새 로그인 항목 이전,
로그 크기 제한, 파일 감시·대체 폴링·디렉터리 복구 검사와 관련 GUI 회귀 검사는 통과했습니다.
아래 10월 15일의 과거 결과를 이번 Debug 실행의 결과로 해석하지 마세요.

alpha.30 배포 준비에서 두 테스트가 누락한 `CoreIpcServer`를 구성하도록 픽스처를 수정했습니다.
검사를 제외하거나 production assertion을 바꾸지 않고 전체 Linux Debug **74/74 통과**를 확인했습니다.

Mac에서는 이전 알파에서 업데이트하는 경우와 새로 설치하는 경우를 모두 확인해야 합니다.
자동 실행 켜기·끄기, 이전 항목 정리 실패 후 재시도, 수동 시작, 로그인 시 숨김,
메뉴 막대 복귀, 재부팅 후 새 `CODESIGNING` 보고서 유무를 검사하세요.
같은 조건에서 CPU·RAM도 비교해야 하며, Linux 수치는 Mac 측정을 대신하지 않습니다.
수치와 조건, 구현 범위는 [후속 검증 기록](../dev/reboot-resource-followup-2026-10-25.md)에 있습니다.

## 2026-10-15 진행 상태

요청한 8개 항목 전체가 완료된 상태는 아닙니다. 아래의 구현과 검증은
배포 완료나 Windows·macOS에서의 해결 확인을 뜻하지 않습니다.

| 요청 | 현재 반영한 내용 | 완료 전에 남은 일 |
| --- | --- | --- |
| 1. Mac 특정 상황 강제 종료 | TIS null 배열 접근, 이벤트 탭·전원 감시 런루프 수명, 클립보드 참조 누수·잘못된 항목 조회, 알림·GUI 스레드 처리 보완 | Mac 빌드·실행, 실제 충돌 보고서로 제보 상황의 원인 확인 및 재현·해결 검증 |
| 2. 재부팅 후 오탐과 오류 보고 실패 | 부팅 ID로 세션 구분, 종료 기록, 코어 종료 대기, 진단 미리보기·복사·저장·브라우저 실패 후 수동 제출 흐름 | Windows·Mac 재부팅·로그아웃 및 실제 브라우저 보고 흐름 확인 |
| 3. CPU·RAM | 공통 시계의 정수 나눗셈 오류 수정, IPC·UI 로그 크기 제한, 보조 타이머·X11 유휴 대기 조정, Mac 클립보드 자원 해제 | Linux 연결 코어의 제한된 전후 비교는 완료. Windows·Mac 전체 앱과 장시간 사용·잠자기에서 비교 필요 |
| 4. Tailscale 첫 연결 안내 | 호스트 대기 상태에서 클라이언트의 대상 선택 안내 유지 | 실제 Tailnet의 다른 호스트에 붙어 있는 클라이언트로 전체 흐름 검증 |
| 5. 호스트 변경 | 실행 중 대상 변경 시 기존 코어 종료 후 새 대상 연결, 중지 시 예약 재시작 취소 | 실제 Tailscale 및 Windows·Mac에서 전환과 입력 도착 확인 |
| 6. 기타 불안정 | 중지 후 늦게 도착하는 복구 콜백 무시, 역할 변경 중 시작 취소, 오류창 제한, 실제 코어의 빠른 전환·호스트 종료 후 복구·앱 종료 검증 | 실제 VPN 단절·복구, 잠자기, 모니터 변경, 장시간 사용 검증 |
| 7. UI/UX 세대교체 | 첫 연결 안내, 설정 개별 검색·직접 이동, 이름·방향으로 컴퓨터 배치, 개별 컴퓨터 설정의 이름·키 매핑·호환성 분리, 수신·단축키·인증서 화면의 시각 규칙 통일, 진단 보고 개편 | 실제 사용자와 전체 흐름 검토, Windows·Mac 권한·다중 모니터·확대 배율·키보드 탐색 확인 |
| 8. README | 과거 버전 나열 제거, 제품 설명·3단계 연결·설정 위치·실제 화면 추가, 설치 안내의 낡은 버전 내용도 제거 | 초보자와 실제 설치본으로 설치부터 입력 공유까지 따라 해 보기 |

Linux X11에서는 별도 가상 화면 3개와 실제 TLS 코어를 사용해 호스트를
10회 교대했습니다. 매번 새 호스트에서 보낸 키 입력과 포인터 이동이
클라이언트 화면에 도착했고, 중지 후 재시작이 취소되는 것도 확인했습니다.
한꺼번에 여러 대상을 골랐을 때 마지막 대상만 시작되고 코어가 한 대만 남는지,
호스트 프로세스를 종료했다가 다시 띄운 뒤 TLS와 입력이 자동 복구되는지도 확인했습니다.
호스트 전환 중에는 실제 취소 버튼으로 재시작을 취소했고, 앱 종료가 코어 종료를 기다리면서
다음 실행의 시작 의도를 보존하는 것도 확인했습니다.
기기 목록은 테스트가 주입했으며 통신은 로컬 루프백입니다. 실제 Tailscale
탐색·VPN 경로와 Windows·Mac 동작을 검증한 결과는 아닙니다.

재현하려면 X11 빌드와 Xvfb, OpenSSL, Python 3, X11/XTest 라이브러리가 있는
Linux에서 다음을 실행하세요. 테스트는 자신의 화면·설정·프로세스를 생성하고
정리하며, 출력 디렉터리에 결과와 로그를 남깁니다.

```sh
python3 tools/tests/run_host_switch.py --build-dir build --output-dir /tmp/ieum-host-switch
```

공통 시계·대기 코드의 회귀 검사는 수정 전 소스에서 실패하고 수정 후 통과했습니다.
Linux에서 500 ms 유휴 대기의 자발적 문맥 전환은 20회에서 2회로 줄었으며,
별도 검사로 이벤트 전달이 보조 폴링을 기다리지 않는 것을 확인했습니다.
자원 측정의 조건, 수정 단계별 수치와 실패한 표본은
[전후 비교 기록](../dev/resource-comparison-2026-10-15.md)에 있습니다.

Linux 빌드와 CTest 등록 대상 73개, 레거시 테스트 27개,
CI Python 테스트 26개가 통과했습니다. X11 메인 창 표시와 인증된 TLS 1.3 /
프로토콜 1.14 연결 및 화면 크기 응답도 확인했습니다. CTest 수에는 기존
테스트가 포함되며, Windows 전용 하위 사례는 Linux에서 건너뜁니다.
이 숫자는 요청한 8개 항목의 완료율을 나타내지 않습니다.
개인정보 처리 관련 Python 테스트 18개도 통과했습니다. 첫 연결·설정·배치·개별 컴퓨터·수신
화면을 실제 Qt/X11에서 캡처해 검토했고, 어두운 팔레트에서도 주요 화면의 대비를 확인했습니다.

Mac 보완은 저장소의 기존 [TIS·이벤트 탭 이슈 #30](https://github.com/Cherry-Company/ieum/issues/30)과
[클립보드 자원 이슈 #29](https://github.com/Cherry-Company/ieum/issues/29)를 현재 코드와 대조한 결과도
반영합니다. 빈 클립보드 조회의 Mac 전용 회귀 사례를 추가했지만 이 환경에서는 실행하지 못했습니다.

## 실제 운영체제에서 확인할 항목

| 시나리오 | 확인할 동작 |
| --- | --- |
| Windows 재시작·종료·로그아웃, 창 열림/트레이 실행 각각 | 다음 실행에 잘못된 충돌 안내가 없고 자동 시작 설정이 유지됨 |
| Mac 재시작·종료·로그아웃, 창 열림/메뉴 막대 실행 각각 | 종료가 창 숨김에 막히지 않고 다음 실행에 잘못된 충돌 안내가 없음 |
| 같은 부팅에서 작업 관리자/강제 종료 후 재실행 | 부팅 ID가 확인되는 시스템에서 종료 안내와 로컬 진단을 제공 |
| 오류 보고, 기본 브라우저 연결 실패 | 진단이 클립보드에 남고 수동으로 열 수 있는 주소를 표시 |
| Tailscale 호스트 A에 연결된 클라이언트에서 B 선택 | 중지·연결을 다시 누르지 않고 A 종료 후 B 연결, 실제 입력도 B에서 도착 |
| A→B→C를 연속 선택 | 마지막 C가 대상이고 코어가 중복 실행되지 않음 |
| 새 호스트 연결 중 중지 | 예약된 재시작을 취소하고 이후 자동으로 재연결하지 않음 |
| 클라이언트가 다른 호스트에 연결된 채 새 호스트 시작 | 새 호스트에 클라이언트 쪽에서 대상을 바꾸라는 안내가 계속 보임 |
| 목록 새로고침, 저장된 호스트 오프라인/목록에서 사라짐 | 다른 온라인 기기로 임의 변경하지 않음 |
| Tailscale 정지·로그아웃·네트워크 단절 후 복귀 | 구체적인 다음 행동을 안내하고 중지하지 않은 연결은 복구됨 |
| 서명 전 알파를 Applications에 설치 후 코어 시작·보안 입력 상태 변경 | 네이티브 알림 API를 호출하지 않고 기동·입력 공유가 유지됨 |
| Mac 잠자기 복귀·모니터 재연결·한영 전환·앱 중지 반복 | 충돌, 커서 유실과 입력 상태 불일치 여부 확인 |
| 30분 유휴, 연결 복구 반복, 로그 폭주 | CPU·메모리·자식 프로세스 수를 수정 전과 같은 조건에서 비교 |

맥 강제 종료를 제보할 때는 이음 버전, macOS 버전, 호스트/클라이언트 역할과 직전 작업을 기록하세요.
macOS 충돌 보고서의 예외 종류와 충돌 스레드 스택이 있으면 네이티브 원인 확인에 도움이 됩니다.
