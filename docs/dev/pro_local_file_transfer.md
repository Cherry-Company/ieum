# Pro Local 파일 전송과 라이선스 발급

`0.1.0-alpha.22`의 Pro Local 파일 전송은 Windows와 macOS 사이에서 직접 동작합니다. 어느 쪽이
서버나 클라이언트여도 화면 토폴로지에 연결된 경계에서 전송을 시작할 수 있습니다. 로컬 KVM,
IME 동기화와 클립보드는 Pro 라이선스 없이 계속 사용할 수 있습니다.

## Early Access 범위와 가격

Pro Local Early Access는 **USD 30 일회성**입니다. 한 번 발급받은 파일은 구매자 자신의 Windows와
macOS 컴퓨터에서 Pro Local 파일 전송을 영구적으로 엽니다.

이 판매는 프리릴리스 기간에만 제공하는 한시적 Early Access입니다. 향후 모든 Pro 기능, Ieum Cloud,
릴레이 사용량, Teams 기능이나 유료 지원 계약을 포함하지 않습니다. 파일 전송 데이터는 Ieum 서버를
거치지 않으므로 이 권한을 사용하는 데 Ieum 계정이나 활성화 서버도 필요하지 않습니다.

## 구매와 수동 발급

1. Ieum에서 **환경설정 → Files**를 엽니다.
2. **Get Pro Local Early Access**를 누릅니다. 앱은 32자리 claim code를 만들고 그 값을 포함한
   GitHub Sponsors 페이지를 엽니다.
3. USD 30 일회성 등급으로 결제합니다.
4. 같은 화면의 **Email license request**를 누르거나 직접 `easecompany@protonmail.ch`로 메일을
   보냅니다. GitHub 사용자명과 앱에 표시된 claim code를 함께 적습니다.
5. 프로젝트 소유자가 GitHub Sponsors의 실제 결제 내역과 claim code를 대조합니다.
6. 확인이 끝나면 소유자가 `*.ieum-license.txt` 파일을 이메일로 보냅니다.

GitHub는 앱에 후원자의 비공개 이메일 주소를 공개하지 않습니다. 그래서 결제 후 요청 메일이
필요합니다. 앱에서 먼저 claim code를 만든 경우 그 코드를 보내고, 앱을 통하지 않고 결제해 claim이
없다면 GitHub Sponsors 영수증을 전달하면 됩니다. 라이선스 파일이나 개인 정보를 공개 이슈에 올리지
마세요.

claim code는 라이선스 자체가 아니며 Pro 기능을 열지 않습니다. 소유자 발급기는 원문 claim 대신
SHA-256만 비공개 발급대장에 저장하고 같은 claim의 중복 발급을 거부합니다. 발급 개인키, 발급기,
발급대장과 비공개 영수증은 공개 저장소나 릴리스에 포함하지 않습니다.

## 설치와 활성화

파일 전송에 참여하는 Windows 또는 macOS 컴퓨터마다 다음을 수행합니다.

1. `0.1.0-alpha.22` 이상을 설치합니다.
2. **환경설정 → Files → Import license file…**에서 받은 `*.ieum-license.txt`를 선택합니다.
3. 유효한 라이선스로 표시되면 **Activate**를 누릅니다.
4. **환경설정 → Network**에서 TLS를 켭니다.
5. 파일을 보낼 컴퓨터에서는 **Send files by dragging them across a screen edge**를 켭니다.
6. 받을 컴퓨터에서는 **Receive files from configured connected computers**를 켜고 절대 경로인 저장
   폴더를 확인합니다. 기본값은 `Downloads/Ieum`입니다.

같은 구매자가 소유한 컴퓨터에는 같은 라이선스 파일을 설치할 수 있습니다. 현재 오프라인 권한은
장치 수를 세거나 장치에 묶지 않으며 원격으로 회수되지 않습니다.

## 파일 보내기

1. Ieum에서 두 화면의 위치를 구성하고 양쪽 컴퓨터를 연결합니다.
2. Finder 또는 파일 탐색기에서 일반 파일을 선택합니다. 폴더, 패키지와 심볼릭 링크는 받지 않습니다.
3. 상대 화면이 배치된 경계로 파일을 끌어 250ms 이상 유지한 뒤 놓습니다.
4. 커서가 넘어가는 대상 컴퓨터의 저장 폴더에 파일이 나타나는지 확인합니다.

동작은 항상 **복사**입니다. 원본 파일은 이동하거나 삭제하지 않습니다. 받는 폴더에 같은 이름이 있으면
기존 파일을 덮어쓰지 않고 `파일 (1).확장자`, `파일 (2).확장자` 순서로 새 이름을 선택합니다. 한글,
공백이 있는 이름과 macOS의 분해형 Unicode 이름은 NFC로 정규화합니다.

Windows→macOS, macOS→Windows 양쪽 방향을 지원하며 서버·클라이언트 역할은 전송 방향을 제한하지
않습니다. 한 번에 최대 100개 파일을 선택할 수 있습니다. 구현은 60 KiB 이하 청크로 읽고 각 파일의
크기와 SHA-256을 확인한 뒤에만 최종 이름으로 게시합니다.

## 보안과 로컬 경계

- 파일 바이트는 이미 연결된 두 컴퓨터 사이의 TLS 스트림으로 직접 이동합니다.
- Ieum 운영 서버, 저장소나 릴레이에는 파일이 업로드되지 않습니다.
- 소스는 제안 수락 후에만 열고, 읽기 직전에 파일 ID·크기·수정 시각을 다시 확인합니다.
- 수신 파일은 권한을 제한한 `.ieum-transfer-*` 임시 디렉터리에 기록합니다. 크기나 SHA-256이 맞지
  않으면 임시 데이터를 정리하고 게시하지 않습니다.
- 서비스 시작, 제안, 수락과 데이터 청크마다 양쪽의 현재 `file-transfer` 권한을 다시 확인합니다.
  라이선스를 제거하거나 만료시키면 진행 중 세션도 실패하며 자동으로 부활하지 않습니다.

현재 Early Access에는 전송별 승인 창, 진행률 화면, 일시정지·재개와 임의의 원격 앱 안으로 바로 놓는
네이티브 드롭이 없습니다. 수신 스위치를 켜는 동작이 연결된 컴퓨터의 전송을 미리 허용하는 방식입니다.

## 오픈 소스와 라이선스 키의 의미

Ieum 데스크톱 코드는 계속 `GPL-2.0-only WITH LicenseRef-OpenSSL-Exception`으로 공개됩니다. GPL
바이너리는 유료로 판매할 수 있지만 구매자는 대응 소스를 받을 권리와 재배포 권리를 유지합니다.
사용자가 공개 코드를 수정해 기능 잠금을 제거한 자체 빌드를 만드는 것까지 막는 DRM은 아닙니다.

Pro Local 파일은 공식 배포 바이너리에서 파일 전송 권한을 확인하는 오프라인 서명 증명입니다. 공개
검증키만 앱에 포함되고 서명 개인키는 소유자만 보관합니다. 장치·계정·원격 회수가 필요한 향후 Hosted
Pro는 별도 서비스 경계로 설계하며 이 영구 로컬 파일전송 권한을 Ieum 운영 대역폭 상품으로 바꾸지
않습니다.

## 문제 해결

| 표시 또는 증상 | 확인할 내용 |
| --- | --- |
| Files 탭이 보이지 않음 | `alpha.22` 이상 Windows 또는 macOS 빌드인지 확인합니다. |
| Pro Local is locked | 받은 파일을 **Import license file…**로 가져온 뒤 **Activate**를 눌렀는지 확인합니다. |
| invalid format/signature | 파일을 편집하거나 여러 줄로 합치지 말고 이메일로 받은 원본을 다시 가져옵니다. |
| not active yet | 컴퓨터의 날짜·시간·시간대가 정확한지 확인합니다. |
| 전송 옵션이 비활성 | 라이선스, 설정 쓰기 권한과 TLS가 모두 유효한지 확인합니다. |
| 경계에서 드롭이 안 됨 | 양쪽 `alpha.22`, 보내기/받기 스위치, 화면 배치와 연결 상태를 확인합니다. 폴더 대신 일반 파일로 시도합니다. |
| 파일이 보이지 않음 | 받는 폴더와 같은 이름의 `(1)`, `(2)` 파일을 확인합니다. 실패한 전송은 임시 파일을 게시하지 않습니다. |
| claim을 잃어버림 | 설정 창을 다시 열면 새 claim을 만들 수 있습니다. 결제한 GitHub 사용자명과 실제 영수증을 함께 메일로 보냅니다. |

`alpha.22`는 프리릴리스입니다. 자동 빌드와 집중 테스트는 소스 재검증, 임시 파일 정리, 이름 충돌,
권한 철회와 Windows/macOS 구현을 다루지만, 실제 두 컴퓨터에서 네 방향의 수용 기록이 완료되기 전에는
안정판으로 표시하지 않습니다.
